# Highlands Borough Floodmapper

Generated from the Avalon template using town-specific gauges, datum offsets, thresholds, overlay roots, and the hard-coded municipal boundary from Towns.shp.

Flood rasters are generated by the portable North Wildwood connectivity pipeline: bounded-cubic one-foot terrain, automatic shared-side source qualification, minimax first-connection stages, five tidal phase families, developed-land attenuation, public-road-only visible feeders, five-foot pooling, and stepped depth classes. Highlands retains its existing colors and its 0.00/0.00/0.00-foot minor/moderate/major attenuation anchors. No separate site-specific bulkhead crest was supplied, so no North Wildwood crest elevation is borrowed.

## Modern Highlands controls

The desktop cards and mobile control drawer share Forecast/Past, Lower end/Mean/Upper end, Choose date, opacity with percentage, and discrete flood-stage bands with uncertainty. Hourly and 15-Min replay are joined by Daily Max, which selects the highest available water level per New York day and retains its timestamp and hydraulic phase. Past Daily Max shows the selected day; use date arrows to move between days. Partial days use the available readings only. This is a peak-water-level frame, not a per-cell maximum-depth composite.

Satellite imagery is available in the live map and PNG/GIF exports. The Highlands-specific guided tour supports the mobile drawer, keyboard focus, and Escape. Interval help explains sampling and data gaps.

North Wildwood's modeled return-period floods, road/structural impacts, parcel inspection, and 3D controls are not enabled: Highlands has no corresponding configured local datasets in this repository. They require Highlands data and validation before being exposed in the UI.


## Ground Elevation Contours

The interactive 2D map's Layers card has an off-by-default
**Ground Elevation Contours** switch.
Contours use 5-foot intervals, with labeled 25-foot index contours, in feet
NAVD88. They remain in that land datum when the water-level display changes
to MLLW. Turning the layer off removes both lines and labels; the setting is
not persisted.

The optional layer uses the documented one-foot calculation DEM, created by
bounded cubic resampling of the one-meter 2022/2014 bare-earth LiDAR mosaic.
Valid 2022 measurements take priority; 2014 measurements fill gaps. NoData
is masked. Contour geometry uses a 0.1-foot horizontal simplification tolerance
and a one-foot minimum input-line length, with Leaflet line simplification
disabled. The original measurements remain one-meter resolution; resampling
adds calculation detail without establishing one-foot survey accuracy.
These terrain contours are independent of flood connectivity, depth rasters,
forecast inputs, and the flood model's terrain configuration. The asset records
source links and SHA-256 hashes for both the source and resampled DEMs.
The separate 3D view and PNG/GIF export renderer do not include this layer.

To regenerate with numpy, Pillow, and contourpy installed:

```sh
python3 tools/build_highlands_contours.py \
  --dem /path/to/HighlandsBorough_2022_2014_1m_NAVD88ft.tif \
  --manifest /path/to/SourceResamplingManifest.json \
  --calculation-dem /path/to/highlands_1ft.tif
```

## Six-hour source refresh

Both forecast and observed refreshes run at `25 2,8,14,20 * * *` UTC.
They share a serialized update group; the optional hourly forecast trigger is
omitted so it cannot displace a queued six-hour observation update. Source jobs use `contents: write`, commit only
validated generated data, and call the publisher directly after the commit.
The publisher overlays generated data on the currently hosted manifest and
preserves every deployed UI/terrain blob. Hosting rejections fail publication
without undoing or preventing the source-data commit.

`data/refresh_status.json` records actual gauge, datum, upstream cycle or latest
measured observation, and SHA-256 digests of generated inputs. Fresh processing
times cannot substitute for recent measurements. Publication verifies the
served generated bytes against the manifest. UI, thresholds, gauges and
scientific model settings are not changed by this schedule.
